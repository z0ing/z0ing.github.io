### 1. 概念定位
这是整个多线程大厦的**地基**。如果你不理解“进程”和“线程”的区别，不知道线程是怎么被创建和跑起来的，后面学锁、学线程池就会像空中楼阁，完全无法理解底层在干嘛。

### 2. 基础知识回顾
因为这是我们的第一个概念，不需要回顾前置的Java多线程知识。但你必须知道一个常识：**Java程序是从 `main()` 方法开始执行的，这个 `main()` 方法本身就运行在一个线程里，我们称之为“主线程”。**

### 3. 基础常态用法速授
> 💡 **提示**：这部分是“死记硬背”的语法事实，直接看懂、记住即可，不需要猜。

**一句话定义**：在Java中，执行代码的最小单位是**线程（Thread）**。要开启一个新的线程去执行任务，最基础的两种方式就是：**继承 `Thread` 类** 或 **实现 `Runnable` 接口**。

**方式一：继承 `Thread` 类**
```java
// 1. 定义一个类继承 Thread，重写 run() 方法
class MyThread extends Thread {
    @Override
    public void run() {
        // 这里写新线程要执行的代码
        System.out.println("新线程在运行: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        // 2. 创建实例
        MyThread t = new MyThread();
        // 3. 调用 start() 启动线程（绝对不能调用 run()！）
        t.start(); 
        System.out.println("主线程在运行: " + Thread.currentThread().getName());
    }
}
```

**方式二：实现 `Runnable` 接口（🌟 工作中最常用）**
```java
// 1. 定义一个类实现 Runnable 接口，实现 run() 方法
class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("新任务在运行: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        // 2. 创建任务实例
        MyTask task = new MyTask();
        // 3. 将任务传给 Thread 对象，并调用 start()
        Thread t = new Thread(task);
        t.start();
        
        // 快捷写法（Lambda表达式），工作中极度常用：
        // new Thread(() -> System.out.println("Lambda线程运行")).start();
    }
}
```

⚠️ **最核心的易错点提醒**：
**启动线程必须调用 `start()` 方法，绝对不能直接调用 `run()` 方法！**
- 调用 `start()`：JVM 会向操作系统申请创建一个真正的底层线程，然后由操作系统调度去执行 `run()` 里的代码（这是真正的多线程并发）。
- 调用 `run()`：这只是一次普通的方法调用，代码依然在当前线程（主线程）里同步执行，根本没有开启新线程！

### 深度解析：`start()` 背后的魔法

刚才你理解了“为什么需要多线程”，现在我们来看看代码里 `start()` 到底干了什么。

当你调用 `t.start()` 时，它并不是简单地调用 `run()` 方法。根据廖雪峰教程和JVM底层原理：

1. `start()` 是一个 **`native` 方法**（底层由C/C++实现）。
2. 它会向**操作系统**申请创建一个真正的“本地线程（Native Thread）”。
3. 操作系统创建好线程后，会把它放入**就绪队列**，等待CPU分配时间片。
4. 当CPU轮到它执行时，操作系统会**自动回调** Java 层的 `run()` 方法。

**一句话总结**：`start()` 是“向操作系统申请新线程并排队”，`run()` 只是“新线程获得CPU后要执行的具体任务”。

### 场景挂靠与反例辨析（实战坑点）

现在，我们知道遇到耗时任务要开新线程了。来看一个工作中极其常见的**反面案例**：

**场景**：老板让你写一个爬虫，需要抓取 **1000个** 网页的内容。
**新手的直觉代码**：
```java
// 反例：直接循环创建1000个线程
for (int i = 0; i < 1000; i++) {
    new Thread(() -> {
        // 执行网页抓取逻辑...
    }).start();
}
```

### 为什么不能无脑 `new Thread()`？（引入“上下文切换”）

假设你的电脑CPU只有 **8个核心**。当你启动了 1000个线程时，操作系统为了让这1000个线程看起来像是“同时”在运行，会使用一种叫 **时间片轮转（Time Slicing）** 的调度策略：
1. CPU给线程A执行 1毫秒。
2. 1毫秒到了，CPU强行暂停线程A，把A当前的状态（寄存器里的数据、执行到了哪一行代码）**保存到内存**中。
3. CPU加载线程B的状态，让B执行 1毫秒。
4. 再保存B，加载C...

🚨 **灾难发生了**：
CPU在这1000个线程之间来回切换，每次切换都要**保存旧状态、加载新状态**，这个动作叫做 **“上下文切换（Context Switch）”**。
上下文切换本身是极其消耗CPU资源的！当线程数量远大于CPU核心数时，CPU可能把 **90% 的时间都花在了“切换线程”上**，而真正用来“抓取网页”的时间只剩 10%。这就是为什么系统会“卡死”——CPU累死了，但没干正事。
